# 写作指南：内容格式

MORI 的文章存成 JSON，不是 Markdown。原因：划词引用评论要钉在具体的文字上，需要稳定的地址；横滚时块还带位置参数，Markdown 表达不好。Markdown 只用于导入导出（见 README）。

写文章主要靠 Studio（默认用 Markdown 写，它替你转成 JSON 并保住划词引用评论要用的块 id）；也可以手写 JSON，或者用 `mori-md import` 把已有的 Markdown 转过来。格式错了，`astro dev` / `astro build` 会指出是哪个文件的哪一处，以及 id 重复、旁注找不到这类错误。

## 一、共有的元信息

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 标题 |
| `subtitle` | | 英文副题（斜体细体） |
| `date` | 是 | `2025-09-14`；决定排序和刻度上的位置 |
| `category` | 是 | 分类 id，必须在 `mori.config.ts` 的 `categories` 里 |
| `tags` | | 标签，字符串数组；Studio 的“分类 / 标签”里管理（网站暂时不按标签筛） |
| `excerpt` | 是 | 一句摘要，目次里标题下面那行 |
| `cover`、`coverAlt` | | 封面图，相对于这个 JSON 文件的路径，如 `"../../assets/a.jpg"` |
| `draft` | | `true` 时只在 `astro dev` 里可见 |
| `pin` | | 置顶，见下 |
| `updated` | | 修改日期，sitemap 用 |

### 置顶（首页“引文开篇”）

有 `pin` 就是置顶，首页最多显示四篇，按 `order` 排；一篇都没置顶时，首页用最新一篇（引文取 `excerpt`）。

```json
"pin": {
  "order": 0,
  "quote": ["六月的冰岛没有夜，", "只有一段很长的黄昏，", "接着又是早晨。"],
  "caption": "冰岛 · 2025.06 · 一号公路",
  "meta": [
    { "label": "日期", "value": "二〇二五年六月" },
    { "label": "篇幅", "value": "约三千二百字 · 图二十五" },
    { "label": "路线", "value": "一号公路环岛，二千一百四十公里" }
  ],
  "image": "../../assets/other.jpg",
  "alt": "图片说明"
}
```

- `quote` 是已经按句读断好行的数组；首行的「和末行的」由主题补。
- `image` 不写就用文章自己的 `cover`；图需要留出放字的地方（天空、雾、水面）。

## 二、行内文字

凡是“文字”的地方（段落、标题、引用、列表项、旁注……）都可以写成：

- 一个字符串：`"这是一段话。"`
- 或者“文字 + 标注”的数组：

```json
[
  { "t": "沿一号公路绕岛一圈，" },
  { "t": "十天", "marks": [{ "type": "note", "ref": "n1" }] },
  { "t": "，两千一百四十公里。" }
]
```

标注 `marks`（从外到内依次包住这段文字）：

| type | 参数 | 效果 |
|---|---|---|
| `em` / `strong` / `code` | | 斜体 / 加粗 / 行内代码 |
| `link` | `href` | 链接 |
| `place` | `lnglat`、`en`、`date` | 地点：标记住的文字是地名，地图上的一个点。`lnglat` 是 **[经度, 纬度]**，`en` 英文名、`date` 日期只用于显示（见第四节） |
| `tcy` | | 竖排里数字横排 |
| `note` | `ref` | 旁注：宽屏放右栏，窄屏内联。正文写在文章的 `notes` 里 |
| `fn` | `ref` | 脚注：文末列出 |

```json
"notes": { "n1": { "text": "旁注或脚注的正文，也是行内文字" } }
```

长卷版式（第四节）里旁注和脚注不分栏，都在文末列成“注”。

## 三、文章（`src/content/posts/`）

`blocks` 是块的数组，每个块有唯一的 `id`（创建后别改，引用评论靠它定位）。

| type | 字段 |
|---|---|
| `p` | `text` |
| `h` | `level`（2 或 3，默认 2）、`text`；二级标题自动编号 01、02…… |
| `quote` | `text`、`cite`、`writing`（`"v"` 竖排） |
| `image` | `src`、`alt`、`caption`、`layout`（`wide` 跨出正文栏 / `inline` 与正文同宽） |
| `list` | `items`（每项是行内文字）、`ordered` |
| `code` | `code`、`lang` |

## 四、横滚与地图（每篇文章都能开）

文章只有一种结构。横滚（读法）和地图是每篇自己的设置，不是另一种“模版”：不开就是上面的竖向文章；开了读法、地图，或者用了下面的图组、自由排布、地图块，页面就换成长卷版式（竖向 / 混合 / 横向三种读法，读者在右下角切换并被记住）。

```json
"reading": { "default": "h", "allowed": ["v", "h", "mix"], "direction": "ltr" },
"map": true,
"facts": [{ "label": "路线", "value": "一号公路环岛" }],
"track": [[-21.9, 64.1], [-21.5, 64.0]]
```

- `reading`：不写就是普通的竖向文章。`default` 默认读法（`v` 竖向 / `h` 横向 / `mix` 混合）；`allowed` 允许读者选哪几种；`direction` 横滚方向（`ltr` 左→右，`rtl` 右→左的手卷）。
- `mapView`：`{ "hero": true, "here": true, "itinerary": true }`，地图开着时分别控制封面路线图、左下角当前位置、文末行程表，不写就都显示；正文里的地图块不受影响。
- `map`：开了以后，封面有路线图（和 `facts`：一行行的“路线 / 日期 / 里程”），左下角显示读到哪个地点，文末有行程表。路线按地点出现的先后连线。
- `track`：可选的轨迹点（GPX 导入或照片 EXIF 生成），不写就按地点顺序连线。
- 地图在构建时生成：按地点范围自动选投影和分辨率，标签自动避让。

### 地图分区

左下角的小地图和默认的地图块只画“当前区域”，不画全程。相邻的地点同属一个区域：和上一处隔得远（超过 150 公里），或者这一区铺得太大（超过 3 度），就自动另起一区。作者可以在地点上改：`region: "new"` 从这里另起一个区域，`"same"` 接着上一处（不管多远）；Markdown 里写在地址后面，如 `geo:35.68,139.7?region=new`，Studio 里在地点的“区域”里选。区域之间的大转移：读到新区域的第一个地点时，小地图先显示一张过渡图（上一区最后一处到这一处），读到这一区的下一个地点再换成这一区的地图。封面的路线图和 `scope: "route"` 的地图块仍然是全程。

### 地点

地点是正文里的行内标记（第二节的 `place`），**不绑定标题**：想标在哪个词上都行。

```json
{ "t": "雷克雅未克", "marks": [{ "type": "place", "lnglat": [-21.94, 64.15], "en": "Reykjavík", "date": "06.20" }] }
```

Markdown 里写成 `[雷克雅未克](geo:64.1466,-21.9426?en=Reykjavík&date=06.20)`（geo URI：纬度在前、经度在后；英文名、日期可不写）。Studio 里选中文字点工具栏的“地点”填写，之后在“信息”里改。地名可以不写：`[](geo:35.01,135.77)`（文字为空的标记）在页面上看不见，只是读到这里时地图跟着变；名字缺省时用英文名，再没有就显示坐标。读到哪个地点：每一列文字记着自己里面出现的第一个地点，没有就沿用上一列的。

### 块

在第三节的块上，还可以有这些，并且所有块都能带位置参数：

| type | 字段 | 说明 |
|---|---|---|
| `pair` | `images`（恰好两张） | 双图并列 |
| `strip` | `images`（每张可带 `scale`、`offset`） | 横向图组：竖向读法是可左右滑动的一行；混合读法钉住后由竖向滚动驱动横移 |
| `grid` | `images` | 多图网格 |
| `free` | `ar`（画布宽高比）、`items` | 自由排布：`{ kind:"image", src, x, y, w, z }`、`{ kind:"text", text, x, y }`，坐标是占画布的比例 |
| `map` | `scope`（`region` 读到的地点所在的区域，默认 / `route` 全程 / `near` 只看读到的地点附近） | 地图 |

- 位置参数：`y`（横滚时上下位置，0 顶 1 底）和 `scale`（缩放）。用比例而不是像素，所以不同屏幕上构图一致。只在横向读法下起作用。
- 横滚时相邻的文字块排成一列，二级标题另起一列；`p`、`h`、`quote`、`list` 可以带 `"writing": "v"` 竖排（竖排和横排不混在一列里）。一列文字的 `y`、`scale` 取列里第一个设了的块（Studio 会写在列里每个块上）。
- 图片的 `layout`：`wide` 在横向读法下就是通栏，`inline` 是内缩。

**用 Markdown 写**：Studio 的 Markdown 视图里就是普通文字——`##` 是二级标题（章节），`###` 小标题，`>` 引用，`-` / `1.` 列表，``` 代码块，图片 `![说明](图.jpg "图注")`，旁注、脚注、地点链接。图组、双图、自由排布里的图在文本里也只是一行行图片，位置、缩放、竖排、地图不出现在文本里。改了文字或图片，Studio 保存时把它们对回原来的块：没动的原样保留，块 id（读者引用评论靠它）、版式、位置都不丢。版式到“排版”视图里摆：它按横向读法把整篇排成一条，上下拖调位置、左右拖换顺序、右下角圆点改大小；选中一块可以换成双图、图组、网格、自由排布，和后一块合并或拆成单图，插入地图，文字可以横排或竖排。

### 以前的游记

以前的游记（`stops` + 每个块属于一站、`text` 块带 `paras`）不用改：读取时自动转成现在的结构——每个站点变成一个二级标题（站名上标着地点，英文名、日期、坐标跟着），文字块里的每一段变成一个块（沿用 id，读者的引用评论不丢），竖排和位置抄到每个块上，`map` 打开，读法、事实、轨迹原样。在 Studio 里改过保存后，文件就是新结构。

## 五、页面（`src/content/pages/`）

“关于”“留言”“友人帐”这样的独立页面。**文件名就是网址**：`about.json` 对应 `/about/`。文件名不能和站点自带的地址重名（`posts`、`archive`、`category`、`search`、`feed`、`travels` 等），构建时会报错。

```json
{
  "title": "关于",
  "subtitle": "About",
  "excerpt": "这本刊物是谁在写。",
  "template": "default",
  "comments": false,
  "draft": false,
  "blocks": [{ "id": "b01", "type": "p", "text": "……" }]
}
```

- 正文的块和文章完全一样（第三节），也可以有 `notes`。
- `template`：`default` 是普通页面；`friends` 是友人帐版式，正文后面接友人帐。
- `comments: true` 时页面底部开放评论。

### 友人帐（`src/content/friends.json`）

一个数组，每位一项：

```json
[{ "id": "a", "name": "某某的花园", "url": "https://example.com/", "desc": "种花，也种一点代码。", "avatar": "https://example.com/icon.png", "order": 0 }]
```

`avatar` 可以是图片网址，也可以是项目里的图（`../assets/xxx.jpg`）；不写就用名字的第一个字。在 Studio 的“友人帐”里粘贴网址会自动带出站名、简介和头像。

## 六、页头入口与订阅（`mori.config.ts`）

```ts
export default defineMoriConfig({
  // 网站顶部玻璃胶囊里的入口。不写的话：文章、归档，再加上所有已发布的页面
  nav: [
    { label: '文章', href: '/posts/' },
    { label: '关于', href: '/about/' },
  ],
  // RSS 订阅（/feed）里放什么：excerpt 只放摘要（默认）；full 放全文
  feed: { content: 'full' },
});
```

在 Studio 里对应“页面 → 页头入口”和“设定 → 订阅”。手机上首页和归档一律横排，不受 `home.direction` / `archive.direction` 影响。
