# 写作指南：内容格式

MORI 的文章存成 JSON，不是 Markdown。原因：划词批注要钉在具体的文字上，需要稳定的地址；游记的块还带位置参数，Markdown 表达不好。Markdown 只用于导入导出（见 README）。

写文章以后主要靠 Studio；在 Studio 做好之前，可以手写 JSON，或者用 `mori-md import` 把 Markdown 转过来。格式错了，`astro dev` / `astro build` 会指出是哪个文件的哪一处，以及 id 重复、旁注找不到这类错误。

## 一、共有的元信息

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 标题 |
| `subtitle` | | 英文副题（斜体细体） |
| `date` | 是 | `2025-09-14`；决定排序和刻度上的位置 |
| `category` | 是 | 栏目 id，必须在 `mori.config.ts` 的 `categories` 里 |
| `excerpt` | 是 | 一句摘要，目次里标题下面那行 |
| `cover`、`coverAlt` | | 封面图，相对于这个 JSON 文件的路径，如 `"../../assets/a.jpg"` |
| `draft` | | `true` 时只在 `astro dev` 里可见 |
| `pin` | | 置顶，见下 |
| `updated` | | 修改日期，sitemap 用 |

### 置顶（首页“引文开篇”）

有 `pin` 就是置顶，首页最多显示四篇，按 `order` 排；一篇都没置顶时，首页用最新一篇（引文取 `excerpt`）。

```json
"pin": {
  "order": 0,
  "quote": ["六月的冰岛没有夜，", "只有一段很长的黄昏，", "接着又是早晨。"],
  "caption": "冰岛 · 2025.06 · 一号公路",
  "meta": [
    { "label": "日期", "value": "二〇二五年六月" },
    { "label": "篇幅", "value": "约三千二百字 · 图二十五" },
    { "label": "路线", "value": "一号公路环岛，二千一百四十公里" }
  ],
  "image": "../../assets/other.jpg",
  "alt": "图片说明",
  "fade": 0.5
}
```

- `quote` 是已经按句读断好行的数组；首行的「和末行的」由主题补。
- `image` 不写就用文章自己的 `cover`；图需要留出放字的地方（天空、雾、水面）。
- `fade`：图朝引文一侧淡出的强度，0 不淡出，1 淡到全透明，默认 0.5。

## 二、行内文字

凡是“文字”的地方（段落、标题、引用、列表项、旁注……）都可以写成：

- 一个字符串：`"这是一段话。"`
- 或者“文字 + 标注”的数组：

```json
[
  { "t": "沿一号公路绕岛一圈，" },
  { "t": "十天", "marks": [{ "type": "note", "ref": "n1" }] },
  { "t": "，两千一百四十公里。" }
]
```

标注 `marks`（从外到内依次包住这段文字）：

| type | 参数 | 效果 |
|---|---|---|
| `em` / `strong` / `code` | | 斜体 / 加粗 / 行内代码 |
| `link` | `href` | 链接 |
| `tcy` | | 竖排里数字横排 |
| `note` | `ref` | 旁注：宽屏放右栏，窄屏内联。正文写在文章的 `notes` 里 |
| `fn` | `ref` | 脚注：文末列出 |

```json
"notes": { "n1": { "text": "旁注或脚注的正文，也是行内文字" } }
```

游记里旁注和脚注不分栏，都在文末列成“注”。

## 三、普通文章（`src/content/posts/`）

`blocks` 是块的数组，每个块有唯一的 `id`（创建后别改，批注靠它定位）。

| type | 字段 |
|---|---|
| `p` | `text` |
| `h` | `level`（2 或 3，默认 2）、`text`；二级标题自动编号 01、02…… |
| `quote` | `text`、`cite`、`writing`（`"v"` 竖排） |
| `image` | `src`、`alt`、`caption`、`layout`（`wide` 跨出正文栏 / `inline` 与正文同宽） |
| `list` | `items`（每项是行内文字）、`ordered` |
| `code` | `code`、`lang` |

## 四、游记（`src/content/travels/`）

游记 = 站点（`stops`）+ 块（`blocks`），每个块属于一个站点（`stop` 写站点 id）。同一份数据按三种读法排版。

```json
"stops": [
  { "id": "rey", "name": "雷克雅未克", "en": "Reykjavík", "lnglat": [-21.94, 64.15], "date": "06.20" }
],
"facts": [{ "label": "路线", "value": "一号公路环岛" }],
"reading": { "default": "v", "allowed": ["v", "h", "mix"], "direction": "ltr" },
"track": [[-21.9, 64.1], [-21.5, 64.0]]
```

- `lnglat`：**[经度, 纬度]**。
- `reading.default`：默认读法（`v` 竖向 / `h` 横向 / `mix` 混合）；`allowed` 是允许读者选哪几种；`direction` 是横滚方向（`ltr` 左→右，`rtl` 右→左的手卷）。读者选的读法会被记住。
- `track`：可选的轨迹点（以后由 GPX / 照片 EXIF 生成）；不写就按站点顺序连线。
- 地图在构建时生成：按站点范围自动选投影和分辨率，站点标签自动避让。

### 位置参数

所有块都可以带 `y`（横滚时上下位置，0 顶 1 底）和 `scale`（缩放）。用比例而不是像素，所以不同屏幕上构图一致。只在横向读法下起作用。

### 块类型

| type | 字段 | 说明 |
|---|---|---|
| `text` | `paras`（每段 `{ id, text }`）、`writing`（`h`/`v`）、`head` | 站点的第一个文字块自动带站点标题；`head: false` 可关掉 |
| `single` | `src`、`alt`、`caption`、`layout`（`full`/`inset`） | 单图 |
| `pair` | `images`（恰好两张） | 双图并列 |
| `strip` | `images`（每张可带 `scale`、`offset`） | 横向图组：竖向读法是可左右滑动的一行；混合读法钉住后由竖向滚动驱动横移 |
| `grid` | `images` | 多图网格 |
| `free` | `ar`（画布宽高比）、`items` | 自由排布：`{ kind:"image", src, x, y, w, z }`、`{ kind:"text", text, x, y }`，坐标是占画布的比例 |
| `map` | `scope`（`route` 全程 / `stop` 只看这一站） | 地图 |

文字块里每个**段落**也要有唯一 id（`paras[].id`）。图片是相对于 JSON 文件的路径，构建时自动压缩成 WebP 并按屏幕宽度出多种尺寸。
