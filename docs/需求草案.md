## 1. 结论

| 问题 | 结论 |
|---|---|
| 项目是什么？ | 一个开源的 Astro 博客主题，加一个本地编辑器 Studio。作者自己的博客是它的第一个使用者。 |
| Astro 能不能满足？ | 能。所有需求都是标准 Web 能力，Astro 负责静态生成，少量交互用 island 按需加载。 |
| 需要做桌面程序吗？ | 不必一开始就做。先做本地网页版 Studio，以后需要时再用 Tauri 打包，界面代码可以直接复用。 |
| 必须用 git 吗？ | 不需要。构建和发布都是 Studio 里的按钮；git 可选。 |
| 部署到哪里？ | Cloudflare Pages 或 VPS，两条路都要支持（见 §6）。 |
| 仓库和许可证？ | https://github.com/Musenxi/Astro-Mori ，GPL-3.0。 |
| 竖排能做吗？ | 能。只要字体带竖排标点（`vert` / `vrt2`）和竖排度量，浏览器直接用 `writing-mode: vertical-rl` 排。 |

## 2. 首页

- 首页除了头条引文旁边的一张封面图，不再放其他照片。首页排法（横排 / 竖排）和归档页（刻度页 E）的排法是两个独立的后台设置，由作者分别决定。
- 保留 F 的两个版本和 E（其余方案已淘汰，见变更记录）：
  - **F 期刊·引文版**（默认首页，方向认可，细节待打磨）：
    - **引文开篇**：
      - 从本期特稿里取一句话，用东观体细体大字排出，按句读手动断行，开头的「悬挂在版心外，进场时逐字像墨一样洇开。
      - 左侧窄栏：“本期特稿”标签（固定，不再有“同时收录”字样）、当前一篇的编号和栏目、期号、季度；紧接着是本期收录的目录（字号比刊期信息大一档），点哪篇就换成哪篇。
      - **封面图**（每篇一张）：一张大图铺在侧栏右边整块（约十栏宽），引文直接压在图上；下面一行小字图注（地点·日期·路线）。图朝着引文的那一侧淡出成纸色，字落在淡出的那一段，所以读得清，又能看出字压着图：横排时引文在左、淡左缘；竖排时引文在右、淡右缘（亮暗两种主题都成立）。图的上边和侧栏对齐，高度约占窗口的六成，保证篇名那一行仍在第一屏。进场时图从上往下展开，只播一次，引文随后逐字洇开。手机上整幅图铺满屏宽、顶到屏幕最上（玻璃页头浮在图上），高度约占屏高八成；引文同样压在图里——竖排时压在右侧（图淡右缘、底缘也淡出），横排时压在底部（图向下淡出），横排的「悬挂在左边；刊期信息、目录放在图下面。图需要留出放字的位置（天空、雾、水面之类）；构图很满的照片，作者可以换图或在 Studio 里调整淡出的强度。
      - 引文下面一条细线，接着是篇名、日期、篇幅、路线和“阅读全文”。
      - 竖排时，引文竖排成三列，像一首诗。
    - **目次**（作者认可）：
      - 左边是大字“目次 / Contents”和编者按，滚动时保持不动。
      - 右边按栏目分组：罗马数字 + 中文栏目 + 英文斜体名 + 篇数。每篇是旧式数字编号、标题、日期和一句摘要。
  - **F 期刊·封面版**（F 的上一个版本，保留备选）：
    - 墨色封面：满版宽度的刊名 MORI（Cormorant Garamond 细体）、期号条、本期特稿（大标题 + 英文斜体副题 + 导语）、右侧四篇封面标题、底部“刊期”刻度（一格一个月，每篇一个点）。暗色模式下封面反成浅底深字。
    - 往下滚时刊名缩小并移到左上角，变成页头里的 MORI；页头压在封面上时自动反色。
    - 目次与引文版相同。
  - **E 刻度**（归档页和栏目页，也可以设为首页）：
    - 位置就是时间，一格一个月，空着的地方就是没写东西（或这个栏目没更新）的月份。旁边的大号年月随滚动逐位翻动。
    - 横排时时间轴往下走；竖排时像手卷一样从右往左展开，标题竖着挂在轴线下。
    - 点目次里的栏目标题进入该栏目的刻度页，栏目标题从目次页原位移动到栏目页顶部。“归档”就是不分栏目的刻度页。
- **置顶与切换**：作者可以置顶零篇、一篇或多篇（首页最多四篇，更多的留给目次）。多篇时，由读者自己点击切换：
  - **怎么切**：点左侧目录里的某一篇；焦点在目录上时，键盘上下方向键也能切。页面照常滚动，不钉住，不跟滚动联动，不自动轮播，也不能拖动或横滑（这几种都试过，被否定：横向拖动“太廉价”，滚动驱动不要）。
  - **目录**：当前一篇高亮（编号变主题色、标题变墨色），上沿画一条主题色细线，切换时细线画过去。
  - **换篇的动效**：交叉溶解（参考 velasx.com 首页精选区）。新旧两篇叠在一起，旧的淡出、新的淡入，同时进行；封面图、引文、图注、篇名信息是一整块，一起溶过去，没有位移、缩放、裁切，引文也不再逐字洇开（逐字洇开只在第一次打开首页时出现）。时长 0.65 秒，先快后慢（quint-out）。左栏的编号和栏目同样淡入。
  - 图注那一行右端标出“02 / 03”。
  - 手机上：图铺满屏宽、顶到屏幕最上（玻璃页头浮在图上），图下面是图注和篇名（只显示篇名和“阅读全文”），再往下是刊期信息和目录。点目录时，如果图已经滚出屏幕，页面把图滚回来。
  - 只有一篇（或没设置置顶）时没有目录，就是一张静止的封面。
  - 没有置顶时，头条取最新文章。
- 需要作者提供的额外字段：每篇一句摘要（目次用）；每篇置顶文章的开篇引文（已断好行）、封面图、一行图注和三条信息（如日期、篇幅、路线）；置顶文章及其顺序。

## 3. 文章类型

### 3.1 普通文章
- 只竖向滚动。
- 元素：标题、元信息（日期 / 字数 / 分类）、正文、二三级标题、引用（可竖排）、旁注（宽屏放右栏，窄屏内联）、单图 + 图注、代码块、列表、脚注。
- 存储格式：JSON，见 §3.3。

### 3.2 游记
**内容模型**：游记 = 站点（stop）列表 + 内容块（block）序列，每个块属于一个站点。同一份数据，按三种读法排版。存储格式同 §3.3。

| 块类型 | 竖向 | 混合 | 横向 |
|---|---|---|---|
| `text` 文字（横排或竖排） | 正文栏 | 同竖向 | 一栏；竖排时高度固定、宽度随内容 |
| `single` 单图 | 通栏或内缩 | 同竖向 | 按作者给的高低、大小放置 |
| `pair` 双图并列 | 两栏 | 同竖向 | 同上 |
| `strip` 横向图组 | 可左右滑动的一行 | 钉住后由竖向滚动驱动横移 | 直接排进横轴 |
| `grid` 多图网格 | 3 列，首图 2×2 | 同竖向 | 2 行，按列排 |
| `free` 自由排布 | 按比例缩放的同一幅构图（手机上退化为两列） | 同竖向 | 一幅画布 |
| `map` 地图 | 通栏 | 同竖向 | 一屏 |

**作者可以指定的位置参数**
- 每个块：`y`（横滚时在上下方向的位置，0 顶、1 底）、`scale`（缩放）、`writing`（文字块横排或竖排）。
- 横向图组里的每张图：`scale`、`offset`（上下错开的量）。
- 自由排布里的每张图：`x`、`y`、`w`（占画布的比例）、`z`（叠放次序）；画布本身有宽高比 `ar`。自由排布里也可以放一小段竖排文字。
- 这些都用比例而不是像素，所以不同屏幕尺寸下构图保持一致。

**阅读方式**
- 竖向 / 横向 / 混合，由读者在右下角切换，并记住上次的选择。作者可以给每篇设默认值，或者只允许其中几种。
- 横滚方向（左→右，或右→左的手卷式）由作者按篇设定。
- 切换读法时回到当前站点的开头，不丢阅读位置。
- 横向滚动不劫持滚轮：页面仍是原生竖向滚动，横移由 `position: sticky` + `transform` 实现，所以触控板、键盘、滚动条都能用。

**地图**
- 剪影地图（默认）：构建时用 d3-geo + Natural Earth 生成 SVG，页面上不加载任何地图 JS。包含轮廓、路线、站点、比例尺、纬线等。
- 专题地图（可选）：MapLibre GL + 自托管 PMTiles，底图样式跟随站点配色，只在需要交互的文章里按需加载。
- 路线来源：手动点选 / 导入 GPX / 从照片 EXIF 的 GPS 自动生成。
- 左下角的小地图标出当前站点，路线随阅读往前画。

### 3.3 存储格式：JSON
- **为什么不用 Markdown**：批注要钉在具体的文字上，需要稳定的地址；游记的块还带位置参数。这两样 Markdown 都表达不好。选 JSON 而不是 XML：表达能力相当，JS 生态里工具更顺手。
- **结构**：一篇文章 = 元信息 + 块序列。每个块有固定 `id`（创建后不变）；段落内部是“文字 + 标注”的序列，不在字符串里嵌 Markdown。旁注、脚注、链接、强调、竖排里的数字横排都是标注。

  ```json
  { "id": "b12", "type": "p", "text": [
    { "t": "沿一号公路绕岛一圈，" },
    { "t": "十天", "marks": [{ "type": "note", "ref": "n3" }] },
    { "t": "，两千一百四十公里。" }
  ]}
  ```

- **校验**：Astro Content Collections 读 JSON，用 zod schema 校验；普通文章和游记各一套 schema。
- **代价**：不适合在普通文本编辑器里手改，git diff 也不如 Markdown 好读。写作以 Studio 为主；提供 Markdown 导入（迁移旧文章）和导出（备份）。

### 3.4 划词批注
- **是什么**：读者用鼠标选中正文里的一段文字，针对这段发表评论。批注就是评论：和普通评论一样显示在文末评论区，只是多带一段被引用的原文。右栏不显示批注，右栏仍只放旁注。只有使用 MORI 自建评论时才有（见 §5）。
- **哪里能划词**：
  - 普通文章的正文。
  - 游记的文字块，竖向、混合、横向三种读法都可以；图片（包括图片条、自由排布里的图）不能。
  - 同一段文字在三种读法里是同一个块，所以在哪种读法下发的批注，定位信息都一样。
- **发批注**：
  - 选中文字后，旁边浮出一颗小玻璃按钮“批注”，和页头同一套质感。
  - 点开后，在选区旁边弹出一个小输入框（手机上从底部弹出），顶部带着引用的原文；发完就收起，读者留在原处继续读，不跳到文末。
  - 横向读法下，文字会随滚动横移：按钮和输入框跟着选区走；输入框打开时暂停跟随，不让它在读者打字时滑出屏幕。
  - 竖排文字里的选区和定位需要单独测试。
- **在评论区里**：
  - 批注和普通评论按时间混排，批注的正文上方先引一段原文（细线引用样式，过长时截断）。
  - 点引用的原文，页面滚回正文里那一段，短暂高亮后淡出。高亮用 CSS Custom Highlight API，不改动正文的 DOM。
  - 游记在横向读法下点引用，不切换读法，直接定位到横轴上的那段文字：取这段文字在横轴上的位置，换算成对应的竖向滚动距离，让它停在屏幕中间（左→右和右→左的手卷式都适用）。
  - 正文里被批注过的文字不留任何记号，只有从评论区点回来时才临时高亮。
  - 回复批注和回复普通评论一样，都在评论区里。
- **定位**：每条批注记录“块 id + 起止字符位置”，同时保存被选中的原文和前后各几十个字（参考 W3C Web Annotation 的做法）。
  - 文章修改后，先按块 id 和位置找；对不上就用原文加前后文匹配；仍找不到时，评论照常显示，引用的原文旁标注“原文已修改”，点击不再跳转。
  - 计算位置时跳过旁注编号、脚注标记等不属于正文的字。
  - Studio 保存时，如果改动会让批注错位，先提醒作者。

## 4. 视觉规范（初稿）

- **字体**：
  - 默认上图东观体（三个字重），朱雀仿宋作为后备和可选字体（只有常规体，使用时关闭伪粗体）。
  - 西文展示字体 Cormorant Garamond（SIL OFL）：刊名、英文副题、编号用它的细体和斜体，旧式数字。
  - 数字、日期、坐标用等宽字体；竖排里的日期改用汉字数字。
- **颜色**：暖纸白底 + 墨色字 + 唯一的主题色（只用于路线、当前位置、游记标记和少量小标签）。
  - 主题色默认克莱因蓝 `#002FA7`，作者在 Studio 里可以改成任意颜色。
  - 作者只选一个颜色，亮色和暗色两个版本自动推出来：在 OKLCH 色彩空间里保持色相和饱和度，亮色模式下亮度封顶（避免浅色在纸上看不清），暗色模式下亮度托底（克莱因蓝在暗色下会提亮成偏浅的蓝）。Studio 同时给出两个版本的预览，也允许手动覆盖。
  - 暗色模式下纸和墨对调。
- **版式**：12 栏网格，正文偏左，右栏放旁注；用细线分隔，不用色块和卡片；图片无圆角、无阴影。
- **磨砂玻璃**：只用于浮在内容上的层：
  - 滚动后的页头：向下滚时收起，向上滚时出现。
  - 右下角的读法切换、左下角的当前位置。
  - 看大图时的背景。
  - 材质是纸色半透明 + 背景模糊 + 很细的颗粒 + 一条细边，不用渐变和发光。
  - 平铺在页面上的内容（卡片、列表）不用。浏览器不支持时退回为不透明纸色。
  - 实现注意：`view-transition-name` 不能放在带玻璃的元素的祖先上（祖先会变成 backdrop root，里面的模糊就看不到背后的内容）；放在玻璃元素自身上没有问题。
  - 页头的液态玻璃（试样中，做法参考 kube.io/blog/liquid-glass-css-svg）：透明玻璃 + 轻模糊 + 提饱和；边缘一圈按凸 squircle 斜面和斯涅尔定律（折射率 1.5）算出折射位移，生成 SVG 位移贴图，通过 `backdrop-filter: url()` 应用；另有一张按边的朝向算出的高光贴图（左上、右下两端最亮）。`backdrop-filter: url()` 只有 Chromium 支持，其他浏览器退回轻模糊 + 高光，边缘不弯。
- **看大图**：点任意图片，图片从原位放大，原来的裁切同步展开；Esc、点击或滚动时关闭，按原路缩回。
- **动效原则**：动画只用来说明“从哪来、到哪去”。
  - 做：页面切换时标题和地图原位过渡（View Transitions）；地图路线随阅读前进；图片进入视口时轻微展开，只播一次；自由排布里的图依次展开。
  - 不做：图片乱飞、逐段淡入、鼠标光晕、视差堆叠。
  - 支持系统“减少动态效果”设置。
- **不要的东西**：渐变背景、发光按钮、阴影圆角卡片、emoji 图标、首屏大口号 + 双按钮。

## 5. 评论

作者在配置里二选一，两条路互相隔离，不做混用或数据互通：

| 方案 | 文末评论 | 划词批注 | 需要什么 |
|---|---|---|---|
| **MORI 自建评论** | 有 | 有（见 §3.4） | Cloudflare Workers + D1，或 VPS 上的 Node + SQLite |
| **第三方** | 有 | 没有 | 按所选服务商 |

### 5.1 MORI 自建评论
- **一套数据**：文末评论和划词批注是同一种评论，区别只是有没有“钉”在文字上（有定位信息的就是批注）。
- **后端**：用 Hono 写，同一份代码跑在 Cloudflare Workers（D1）和 VPS（Node + SQLite）上，SQL 相同。
  - 一张评论表：文章、块 id、起止位置、被选中的原文和前后文（文末评论为空）、正文、昵称、邮箱哈希、时间、状态（待审 / 通过 / 隐藏）、回复对象。
  - 接口：读取某篇文章的评论、提交、回复；管理接口（通过、隐藏、删除）只接受 Studio 持有的管理令牌。
- **防垃圾**：Cloudflare Turnstile（免费人机验证）+ 按 IP 限流；第一次留言的人默认先审后发。
- **管理**：不另做后台，放进 Studio：待审列表、一键通过 / 隐藏 / 删除、新评论数量。
- **通知**：第一版不做邮件，只在 Studio 里显示新评论数量。
- **工作量**：批注不进右栏之后，前端省掉了最费事的右栏排位；主要剩划词取位置、输入框、评论区里的引用和回跳高亮。

### 5.2 第三方评论
| 服务 | 适合 | 需要什么 |
|---|---|---|
| Artalk | 有 VPS、想要成熟的后台和邮件通知 | 一台一直在线的服务器（Go 程序或 Docker，默认 SQLite） |
| Giscus | 只用 Cloudflare、读者多是开发者 | GitHub 仓库；读者需要 GitHub 账号 |
| Waline / Twikoo | 只用 Cloudflare、不想维护服务器 | 免费的无服务器平台 + 数据库 |

选第三方时没有划词批注，正文里也不出现划词按钮。

### 5.3 两种方案共用的部分
- **位置**：评论区放在文章末尾；游记放在行程表之后，横滚部分不受影响。
- **懒加载**：评论区进入视口时才加载脚本，不拖慢首屏。
- **页面切换**：每次进入新页面，都用新的页面标识重新加载评论。
- **样式**：评论框（自建或各家第三方）都改写成本站的纸、墨、字体和细线。

## 6. 部署

**Cloudflare Pages**
- Studio 用 Wrangler 直接上传 `dist/`，不需要 git。
- 限制：免费版每个站点最多 20,000 个文件（付费版 100,000），单个文件最大 25 MiB。
- 游记图片会按多种尺寸、多种格式输出，照片一多很快会接近上限。所以图片多时，把图片放到 Cloudflare R2，页面留在 Pages，Studio 发布时分两步上传。
- 评论：MORI 自建评论直接跑在 Workers + D1 上；或者选第三方 Giscus / Waline / Twikoo。

**VPS**
- 上传：用 rsync 或 SFTP 上传静态文件。
- 模板：提供 Docker Compose 模板，包含 Caddy（自动 HTTPS）、静态站和评论服务（MORI 自建评论或 Artalk，二选一），一台机器全部搞定。
- 限制：没有文件数量上限。

**可选**
- 为习惯用 git 的使用者提供 GitHub Actions 模板。

## 7. 技术方案

- Astro + Content Collections（JSON 内容，普通文章与游记两套 zod schema）
- 评论服务：Hono（Cloudflare Workers + D1 / Node + SQLite）、Cloudflare Turnstile；前端批注高亮用 CSS Custom Highlight API
- 页面切换：Astro `<ClientRouter />`（View Transitions）
- 平滑滚动（可选）：Lenis
- 图片：构建时用 sharp 生成 AVIF / WebP 多尺寸，读取 EXIF（时间、GPS）；处理结果本地缓存，避免每次全量重算
- 字体：cn-font-split 子集，按 unicode-range 按需加载
- 地图：d3-geo（构建期）/ MapLibre GL（运行时，可选）
- 输出：纯静态文件

## 8. 编辑器（Studio）

- **形态**：`npm run studio` 启动本地网页，直接读写项目里的内容文件；以后可用 Tauri 打包成双击打开的桌面程序。
- **普通文章**：所见即所得的块编辑，内容存为 JSON；可以用 Markdown 快捷输入（如 `##`、`>`），实时预览用真实主题渲染。支持导入 Markdown（迁移旧文章）和导出 Markdown（备份）。
- **评论管理**（使用 MORI 自建评论时）：待审列表、通过 / 隐藏 / 删除、新评论数量；保存文章时如果改动会让批注错位，先提醒。
- **游记**：块编辑器。
  - 拖入照片自动生成块，可切换块类型、拖动排序，文字块可切换横排或竖排。
  - 在横滚预览里直接拖动块的高低和大小；自由排布里逐张拖动图片、调整宽度和叠放次序（试样里的“作者设置”就是这个交互的雏形）。
  - 在地图上点选站点；从 EXIF 读取时间和位置，自动建议站点。
  - 文章设置：默认读法、允许的读法、横滚方向。
- **主题色**：取色器 + 几个预设（默认克莱因蓝），实时预览亮色和暗色两个版本，可手动覆盖暗色版本；保存到 `mori.config.ts`。
- **字体**：拖入任意字体文件，自动用 cn-font-split 切分并写好配置。同时提示使用者自行确认字体授权，以及字体是否带竖排标点。
- **构建**：一键运行 `astro build`，显示进度和报错。
- **发布**：一键上传，目标可选 Cloudflare Pages（+ R2）或 VPS（rsync / SFTP）。
- **git**：可选，只用来备份版本。

## 9. 开源

- **分发形式**：主题包 + 模板。主题逻辑做成 npm 包（Astro 集成），模板只放内容和配置，升级只需更新包版本。仓库用 monorepo：`packages/theme`、`packages/studio`、`examples/demo`。
- **配置**：一个 `mori.config.ts`，包含站点名、导航、首页方案、主题色（默认克莱因蓝）、字体、默认读法、界面语言、评论服务、发布目标。
- **字体**：
  - 上图东观体：默认字体，按作者决定放进仓库（版权归上海图书馆）。
  - 朱雀仿宋 v0.212（SIL OFL 1.1，无保留字体名）：随主题附带，切分后可直接分发，附上 OFL 协议文本。带竖排标点（`vert` / `vrt2`），没有竖排度量表，浏览器会自动补齐。
- **多语言**：
  - 界面文字抽成语言包，至少 zh-CN / zh-TW / en / ja。
  - 竖排和手卷方向只对中日文内容有意义，英文内容里自动隐藏这些选项。
- **许可证**：GPL-3.0（仓库已设置）。示例内容单独说明：
  - 示例照片用作者自己拍的或 CC0 图片，试样里的占位图不进仓库。
  - 地图数据来自 Natural Earth，属于公有领域。
- **文档**：安装、写作指南（两种文章、每种块的参数）、部署（Cloudflare / VPS）、评论接入、字体替换。
- **名称**：发布前查一下 MORI 在 npm 和 GitHub 上是否重名。

## 10. 分阶段

| 阶段 | 内容 |
|---|---|
| P0 | 风格定调（基本完成，收尾见 §12） |
| P1 | 主题骨架：首页、普通文章、游记三种阅读方式、竖排、自由排布、剪影地图、图片流水线、配置文件 |
| P2 | Studio：内容读写、实时预览、可视化排版、构建、发布到 Cloudflare / VPS |
| P3 | MORI 自建评论（含划词批注）、第三方评论接入层、专题地图、GPX 导入、EXIF 自动建站点、RSS / 搜索、多语言 |
| P4 | 开源发布：文档、示例站、Docker Compose 与 GitHub Actions 模板、Tauri 打包 |

**开发顺序（2026-09-29 定）**：内容格式 → 主题 → Studio → 评论服务。
- **为什么先主题、后 Studio**：Studio 存的 JSON 长什么样（有哪些块、每块带哪些参数）由主题要怎么排决定，先做主题格式才会在真实排版里定下来，先做 Studio 容易返工；Studio 的实时预览本身要用主题渲染；主题可以先用手写的示例文章跑起来，风格能继续在真实页面上调。
- **代价和缓解**：做主题期间写文章要手改 JSON。先写一个 Markdown → JSON 的小脚本，普通文章用 Markdown 写；游记的图片位置暂时手填数字，等 Studio 的拖拽排版。
- **P1 的第一步**：定内容格式（普通文章、游记两套 zod schema，块类型、行内标注、块 id 规则、置顶和首页字段）+ 写几篇示例文章（至少：一篇普通文章含旁注 / 脚注 / 竖排引文；一篇游记含全部块类型；三篇置顶，带封面、引文、图注、三条信息）。格式定下来再搭 Astro 主题骨架。

  - 桌面：点左侧目录三篇能切换、交叉溶解正常；左栏和舞台不再钉住，页面能一路滚到目次；控制台无报错。
